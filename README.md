## Overview

The Digital Asset Threat-Led Security Assessment Framework is a technical assessment aid designed to help security teams validate whether technical controls withstand realistic attack paths across digital-asset environments.

It emphasizes evidence-based validation rather than relying only on the presence of policies, security products or documented procedures. The framework addresses security considerations across enterprise infrastructure, identity, cloud, custody, wallet operations, blockchain infrastructure, smart contracts, third parties, monitoring and incident response.

## Framework at a glance

| Component | Version 1.0 baseline |
|---|---:|
| Core technical controls | 109 |
| Security domains | 16 |
| Core attack-path scenarios | 15 |
| Incident-based test cases | 16 |
| Incident records | 11 |
| Optional supplemental controls | 22 |
| Supplemental attack-path scenarios | 10 |

The 22 supplemental controls and 10 supplemental attack-path scenarios are optional, architecture-dependent modules. They do not change the 109-control core baseline.

## Intended users

The framework may be useful to CISOs and cybersecurity leaders, digital-asset exchanges, digital-asset custodians, wallet and key-management providers, blockchain and Web3 infrastructure operators, security architects, technical assessors and cybersecurity advisory professionals.

## How to use the framework

1. Read the Start Here Guide and Assessment Methodology before testing.
2. Establish the legal entity, services, architecture, assets and assessment scope.
3. Determine which core and supplemental controls apply.
4. Execute tests only within an approved scope and authorized environment.
5. Record reproducible evidence, results, findings and remediation.
6. Independently retest remediation before closing findings.

Use test identities, test keys, test wallets, local forks, testnets and isolated environments. Do not conduct intrusive validation against live customer funds or production private keys without explicit authorization and safeguards.

## Scope and limitations

This is a technical security assessment aid. It is not a regulatory standard, certification scheme, legal opinion, regulatory compliance conclusion or guarantee against security incidents or asset loss.

Regulatory applicability depends on the relevant legal entity, jurisdiction, licence, regulated activities and services. Crosswalk mappings indicate potential relationships and technical coverage only; they do not establish compliance with an entire law, regulation or standard.

The framework should be tailored to the assessed architecture, operating model, technology stack and risk profile. Incident-to-control mappings are assessment hypotheses and test prompts, not proof that a particular control would certainly have prevented a historical incident.
